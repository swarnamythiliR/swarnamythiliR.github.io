107M+

Faster loads on a very large table

Azure Data Factory

A pipeline processing more than 107 million records had a bottleneck of over three hours.

I introduced parallel processing and partition and range-based workload distribution so the load no longer ran as one long serial job.

Catching hard deletes

ADLS · Source data

The upstream source did not send delete timestamps, so removed rows silently stayed in the lake.

I implemented an ADLS purge strategy that identifies and captures those hard deletes, keeping downstream data consistent with the source.
